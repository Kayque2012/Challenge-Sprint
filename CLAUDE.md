## Project Overview

**Turma do Bem** — a volunteer dental care platform connecting vulnerable youth with volunteer dentists. A React SPA with role-based dashboards and a priority-scoring algorithm ("Score TdB") to rank patients by urgency.

Backend: Java/Spring API hosted on Azure (`challengesprint-api.azurewebsites.net`). The frontend communicates via `fetch` using the base URL from `src/config.ts`.

## Commands

```bash
npm run dev           # start dev server (localhost:5173)
npm run build         # tsc -b && vite build
npm run typecheck     # TypeScript check only (no emit)
npm run lint          # ESLint
npm run test          # run all tests once
npm run test:watch    # vitest in watch mode
npm run test:coverage # coverage report (v8, html + text)
npm run check         # tsc + eslint + vitest (pre-commit gate)
npm run coords:update # regenerate src/data/latamCoordinates.ts from the Nominatim script
```

To run a single test file:
```bash
npx vitest run src/test/scoreUtils.test.ts
```

## Local Environment

Create `.env.local` in the project root (already gitignored):
```
VITE_API_URL=http://localhost:8080
```
Without it, the app hits the Azure production API. `src/config.ts` strips the Windows BOM that some editors insert into `.env` files.

## Architecture

### Routing (`src/Routes/index.tsx`)
All routes live in one file. **There are no centralized route guards** — each dashboard (`AdminDashboard`, `DentistaDashboard`, `PacienteDashboard`) performs its own auth check in a `useEffect` on mount and calls `navigate('/login')` if the session is missing or the role is wrong.

### Auth / Session
Login writes three keys to `sessionStorage`:
- `userRole` — `'admin' | 'dentista' | 'paciente' | 'dev'`
- `usuarioLogado` — display name
- `userId` — numeric ID as string

`dentistaCidade` is also written when the logged-in user is a dentist, and is read by `DentistaDashboard` to filter the patient queue geographically. The `'dev'` role gives dentist-dashboard access (for testing).

### Score Algorithm (`src/utils/scoreUtils.ts`)
Pure functions, no side-effects — the only utility with unit tests. Score = `gravidade (0–45)` + `financeiro (0–35)` + `idade (0–20)`. All weight tables are exported constants.

### Report Generation (`src/utils/relatorioUtils.ts`)
`imprimirRelatorio` opens a new browser tab with self-contained HTML and triggers `window.print()`. `buildRelatorioHtml` is the pure builder (testable without a DOM).

### Maps (`src/components/MapaRota.tsx`)
Uses `react-leaflet` + `leaflet.heat` for heatmap overlays. City coordinates come from `src/data/latamCoordinates.ts` (generated by `scripts/generateCoordinates.mjs` via Nominatim).

### Styling
Tailwind CSS v4 via `@tailwindcss/vite` plugin. The single CSS entry point is `src/stl.css`. Tailwind directives are declared there; no `tailwind.config.js` exists (v4 uses CSS-first config). Inline Tailwind classes are used throughout — no CSS modules or styled-components.

### Testing (`src/test/`)
Vitest with `jsdom` environment. Setup file imports `@testing-library/jest-dom`. Tests cover: login form behavior (`login.test.tsx`), route rendering (`routes.test.ts`), and the score algorithm (`scoreUtils.test.ts`). Coverage is collected only from `src/pages/**` and `src/utils/**`.

## Deployment

Vercel. `vercel.json` rewrites all routes to `index.html` for SPA navigation. The GitHub Actions workflow (`.github/workflows/vercel-deploy.yml`) deploys on push. The `VITE_API_URL` environment variable must be set in the Vercel project settings.
